# Jaffery Center of Roanoke website

A six-page community website. Page content is generated from `build.py`; React/TypeScript provides the server-rendered, hydrated navigation without replacing the page markup. Original DeadlineOS files (`app.js`, `fx.js`, `orbitos-dev`) are preserved in the checkout and are not loaded by this site.

## Run and build

```sh
npm install
npm run dev         # Vite preview on port 5173
npm run typecheck
npm run build       # regenerates all six pages, then outputs dist/
npm test            # checks generated pages, links, active nav and assets
```

Edit page copy and links in `build.py`, then run `npm run build` (or `python3 build.py` after dependencies are installed). The generated HTML pages are also checked in for easy review. Shared styles are in `styles.css`; progressive-enhancement behavior is in `site.js`. The desktop glass navbar CSS is in `components/ui/liquid-glass-navbar.css` and is loaded as a stylesheet to avoid a CSS-text hydration mismatch. The mobile menu and desktop navbar share `src/navbar-config.tsx` and `src/site-navigation.tsx`; `src/render-nav.tsx` embeds the React markup in each page and `src/navbar-entry.tsx` hydrates it.

The project has React, TypeScript, Tailwind CSS, and a shadcn-compatible `components/ui` structure (`components.json` points `@/components/ui` to `/components/ui`). Tailwind preflight is disabled to preserve the existing site styling. The navbar now uses a single CSS glass capsule instead of the former shader/canvas + duplicate CSS indicator. The URL/SSR active link is authoritative; DOMRect measurements, ResizeObserver and font-loading events keep the decorative capsule aligned without an animation loop. Reduced-motion navigation switches instantly. The mobile experience is a labeled, keyboard-accessible glass menu in the sticky top header, not a bottom dock.

`components/ui/glsl-hills.tsx` adapts the supplied Three.js shader as a reusable decorative component; `components/ui/glsl-hills-demo.tsx` demonstrates it. `build.py` inserts a decorative mount behind the hero on **all six pages**, and `src/hills-entry.tsx` lazy-loads the effect on screens 768px and wider when motion is permitted. The component accepts `width`, `height`, `cameraZ`, `planeSize`, and `speed` props; the site uses the defaults except for a slower `speed={0.18}`. It requires no provider, state store, image asset, or icon. Its canvas is hidden from assistive technology and cannot intercept clicks. The site's existing gradient provides the mobile, reduced-motion, unsupported-WebGL, and no-JavaScript fallback. Rendering pauses when the hero is offscreen or the tab is hidden, and GPU resources are disposed on unmount. The shader is a lazy-loaded ~130 kB gzip chunk on desktop, not part of the initial mobile payload. Edit the mount in `build.py`, not generated page HTML.

## Proposed visual identity and glass materials

`assets/brand/jc-star.svg` reconstructs the described black, double-line green star and silver JC monogram as vector geometry, with the J/C outlines derived from the licensed Instrument Serif font. The wordmark remains live HTML text. `jc-favicon.svg` is the simpler favicon. The earlier mihrab files and original star remain for restoration; obtain organizational approval before adopting the new identity permanently. `brand-theme.css` defines the near-black/green/silver tokens and overrides the previous light skin while retaining its layouts and glass treatments. It also adds restrained ambient green light and a scroll-progress line; `site.js` batches their updates with existing scroll and pointer behavior. The hero artwork remains explicitly illustrative, not a photograph of the building.

The headings and italic accents use self-hosted [Instrument Serif](https://github.com/google/fonts/tree/main/ofl/instrumentserif), body text uses self-hosted [Inter Tight](https://github.com/google/fonts/tree/main/ofl/intertight), and the Arabic invocation uses [Noto Naskh Arabic](https://github.com/google/fonts/tree/main/ofl/notonaskharabic). Their SIL Open Font Licenses are in `assets/fonts/`; there are no runtime font requests to third-party sites. Previously shipped IBM Plex Sans and Source Serif 4 files are preserved but no longer used in the current theme.

## Meadow Rise footer

`components/ui/meadow-rise-footer.tsx` is a lightweight, React-only adaptation of the supplied Meadow Rise concept. Its six canvas ridges are painted on mount/resize rather than continuously animated; it has no simulated newsletter, social links, or placeholder destinations. `build.py` derives the footer’s JSON configuration from `PAGES`, `EMAIL`, `MAP_URL` and the existing Arabic invocation, while keeping the original static `<footer>` inside `#footer-root`. `src/footer-entry.tsx` lazy-loads the React component only when the footer is within 600px of the viewport. JavaScript disabled, import failure, or an unavailable canvas leaves a readable footer. The footer copy says everyone is welcome and links to real programs, not a “plan your visit” workflow. The visual is dark to match the updated logo rather than the original light-green preset.

## Safe migration and Vercel

This work sits on a branch of the unrelated DeadlineOS repository. PR #4 targets `main`, where `index.html` is the DeadlineOS app, and it has a real merge conflict. **Do not merge this PR into `main`.** PR #4 currently receives a passing Vercel check in the **existing DeadlineOS Vercel project**; that preview is not an independently configured Jaffery site or an official-domain launch. The recommended destination is a dedicated, organization-approved GitHub repository and a *new* Vercel project. Run `python3 scripts/export_standalone.py` to produce an ignored `standalone-export/` folder containing only the Jaffery site and its dependencies; the script refuses nonempty destinations and never deletes or changes DeadlineOS files. Read `docs/STANDALONE.md` (also copied as the export's README) for repository and Vercel steps. The export includes its own `vercel.json`, while this DeadlineOS checkout deliberately does not: a root Vercel config here could affect the existing DeadlineOS project. The export's Vercel build uses `npm run build:vercel` (checked-in generated HTML + Vite), avoiding a Python requirement in Vercel. Regenerate and commit the HTML locally whenever `build.py` changes. No official domain is configured here.

## Liquid glass 2.0 QA

The nav audit found competing WebGL/CSS indicators (the canvas appeared after hydration and could flash over the fallback), `offsetLeft` plus padding measurements that shifted the drop, a `sessionStorage` previous-selection replay that could survive refresh/back, and a second active-link background. The rewrite removes the shader and replay. A single capsule is positioned from the active link’s actual DOM bounds; the server-rendered active background remains visible only until JavaScript measures it. Clicking begins a glide without delaying native page navigation. The follow-up motion pass avoids the first-paint slide, batches scroll reads, pauses the decorative hero glow offscreen, defers terrain loading until idle, and adds cancellable filter transitions. Revealed content never becomes fully transparent, even if observation fails. We deliberately keep native page navigation rather than enabling cross-document view transitions that can wipe the page or duplicate the sticky header. All six pages were browser-tested at 320, 390, 768, 1024, and 1440px without overflow, console errors, or incorrect active links; 12 successive desktop link navigations, reload, back, scrolling, resizing, and mobile Escape/focus behavior passed. Full-page desktop/mobile captures are in `qa/`. Axe WCAG A/AA scans at 390 and 1440px reported zero violations on all six pages. Additional checks covered rapid repeated filtering, rapid address copying and label reset, reduced motion, and simulated WebGL context loss/restoration without browser errors. No real payment submission or actual recipient email delivery was performed; those remain external to this static website. The PR still needs a safe integration decision for the separate DeadlineOS `main` page. For the black/green rebrand, all six pages were retested at 320, 390, 768, 1024, and 1440px; the lazy footer was also checked at 375, 768, and 1440px on every page, with one footer landmark and no overflow or browser errors. Import failure and disabled JavaScript both preserve the static footer. Axe WCAG A/AA scans with the React footer loaded reported zero violations on all six pages at 375 and 1440px. Measured WCAG contrast ratios include body text #e6e6e0 on #060907 at 15.96:1, muted #a3aaa1 on #0c120d at 7.96:1, bright green #49c24a on #060907 at 8.67:1, and button text #e6e6e0 on #1e6427 at 5.76:1. Third-party email delivery, payments, and real-device browser behavior are not verified.
